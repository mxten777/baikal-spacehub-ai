## 1. 시스템 개요

### 1-1. 플랫폼 구성

| 구성 요소    | 기술                         | 역할                       |
| ------------ | ---------------------------- | -------------------------- |
| 프론트엔드   | React 19 + TypeScript + Vite | 공개 웹사이트 + 어드민 CMS |

| 환경      | URL                                           |

| 로컬 개발 | `http://localhost:5173/admin`                 |

| 프로덕션  | `https://thelit.kr/admin` (도메인 연결 후)    |

## 2. 관리자 계정 설정

### 2-1. 최초 관리자 계정 생성

1. [Supabase 대시보드](https://supabase.com/dashboard) 접속
2. 프로젝트 선택 → **Authentication → Users** 메뉴 이동
3. **Invite user** 버튼 클릭 → 관리자 이메일 입력
4. 초대 이메일 수신 후 비밀번호 설정 완료
5. Supabase **SQL Editor**에서 아래 쿼리 실행:

```sql
UPDATE public.profiles
SET role = 'admin'
WHERE email = 'your-admin@email.com';
```

### 2-2. 로그인 절차

1. `/admin/login` 접속
2. 이메일과 비밀번호 입력
3. **로그인** 버튼 클릭
4. 인증 성공 시 `/admin` 대시보드로 자동 이동

### 2-3. 로그아웃

어드민 사이드바 하단 **로그아웃** 버튼 클릭 → 세션 종료 후 로그인 페이지로 이동

### 2-4. 비밀번호 변경

1. Supabase 대시보드 → **Authentication → Users**
2. 해당 사용자 선택 → **Reset password** 클릭
3. 또는 로그인 페이지에서 **비밀번호 찾기** 링크 사용

### 2-5. 다중 관리자 추가

동일한 방법으로 여러 관리자를 등록할 수 있습니다.  
각 계정에 대해 SQL로 role을 'admin'으로 설정해야 합니다.

## 4. 공간 관리

**메뉴 경로**: `/admin/spaces`

### 4-1. 공간 목록 보기

등록된 모든 공간이 테이블 형태로 표시됩니다.

| 컬럼      | 설명                                            |
| --------- | ----------------------------------------------- |
| 이름      | 공간 한국어 이름                                |
| 카테고리  | cafe / garden / studio / storage / hall / other |
| 수용인원  | 최대 수용 가능 인원                             |
| 면적      | ㎡ 단위                                         |
| 대관료    | 시간당 금액 (원)                                |
| 예약 가능 | 토글 (Yes/No)                                   |
| 액션      | 수정 / 삭제                                     |

### 4-2. 새 공간 등록

1. **+ 공간 추가** 버튼 클릭
2. 폼 입력:

| 필드            | 필수 | 설명                                            |
| --------------- | ---- | ----------------------------------------------- |
| 이름            | ✅   | 한국어 공간 이름 (예: 루프탑 카페)              |
| 영문 이름       |      | 영문 이름 (예: Rooftop Cafe)                    |
| 슬러그          | ✅   | URL 식별자 (영문+숫자+하이픈, 예: rooftop-cafe) |
| 카테고리        | ✅   | 드롭다운 선택                                   |
| 설명            |      | 공간 소개 텍스트                                |
| 수용인원        |      | 숫자 입력                                       |
| 면적(㎡)        |      | 숫자 입력                                       |
| 시간당 대관료   |      | 숫자 입력 (원)                                  |
| 커버 이미지 URL |      | 이미지 URL 직접 입력                            |
| 시설/특징 태그  |      | 쉼표로 구분 (예: 빔프로젝터, 음향시설, 에어컨)  |
| 예약 가능       | ✅   | 체크박스                                        |

3. **저장** 버튼 클릭

### 4-3. 공간 수정

1. 해당 공간의 **수정** 버튼 클릭
2. 필드 수정 후 **저장**

### 4-4. 공간 삭제

> ⚠️ **주의**: 삭제 시 복구 불가. 신중히 진행하세요.

1. 해당 공간의 **삭제** 버튼 클릭
2. 확인 대화상자에서 **삭제 확인**

### 4-5. 슬러그 규칙

- 영문 소문자, 숫자, 하이픈(`-`)만 사용
- 공백 불가 (하이픈으로 대체)
- 예: `cafe-lounge`, `garden-yard`, `main-studio`
- 한 번 설정 후 변경 시 기존 공유 링크가 깨질 수 있으므로 신중히 설정

## 5. 프로그램 관리

**메뉴 경로**: `/admin/programs`

### 5-1. 프로그램 상태 정의

| 상태        | 표시    | 의미         |
| ----------- | ------- | ------------ |
| `upcoming`  | 예정    | 아직 시작 전 |
| `ongoing`   | 진행 중 | 현재 진행 중 |
| `closed`    | 종료    | 마감/종료됨  |
| `cancelled` | 취소    | 취소됨       |

### 5-2. 프로그램 카테고리

| 카테고리      | 한국어 |
| ------------- | ------ |
| `exhibition`  | 전시   |
| `performance` | 공연   |
| `lecture`     | 강연   |
| `workshop`    | 워크숍 |
| `event`       | 이벤트 |

### 5-3. 새 프로그램 등록

| 필드            | 필수 | 설명                          |
| --------------- | ---- | ----------------------------- |
| 제목            | ✅   | 프로그램 제목                 |
| 슬러그          | ✅   | URL 식별자                    |
| 카테고리        | ✅   | 상단 카테고리 목록 참조       |
| 상태            | ✅   | 상단 상태 목록 참조           |
| 짧은 설명       |      | 목록 카드에 표시될 한 줄 소개 |
| 상세 설명       |      | 마크다운 가능                 |
| 시작일          |      | YYYY-MM-DD 형식               |
| 종료일          |      | YYYY-MM-DD 형식               |
| 무료 여부       |      | 체크박스                      |
| 가격            |      | 유료 시 금액 (원)             |
| 커버 이미지 URL |      | 이미지 URL                    |
| 신청 URL        |      | 외부 신청 링크                |
| 메인 노출       |      | 홈페이지 메인에 노출 여부     |

### 5-4. 프로그램 노출 관리

- **메인 노출(is_featured)** 체크 시 홈페이지 "예정 프로그램" 섹션에 표시됨
- 상태가 `upcoming` 또는 `ongoing`인 프로그램만 홈페이지에 노출
- 한 번에 최대 4개까지 홈페이지에 표시됨 (최신 등록순)

## 7. 블로그 관리

**메뉴 경로**: `/admin/blog`

### 7-1. 블로그 카테고리

카테고리는 Supabase DB의 `blog_categories` 테이블에서 관리합니다.  
SQL로 직접 추가하거나, 어드민 UI가 지원될 경우 폼을 사용합니다.

```sql
INSERT INTO blog_categories (name, slug)
VALUES ('전시 리뷰', 'exhibition-review');
```

### 7-2. 블로그 포스트 작성

| 필드            | 필수 | 설명                             |
| --------------- | ---- | -------------------------------- |
| 제목            | ✅   | 포스트 제목                      |
| 슬러그          | ✅   | URL 식별자                       |
| 카테고리        |      | 드롭다운 선택                    |
| 발췌문          |      | 목록 미리보기 텍스트             |
| 내용            | ✅   | 마크다운 형식 본문               |
| 커버 이미지 URL |      | 포스트 대표 이미지               |
| 발행 여부       |      | 체크 시 공개, 미체크 시 임시저장 |
| 메인 노출       |      | 홈페이지/목록 상단 노출          |

### 7-3. 발행 관리

| 상태                                  | 설명                       |
| ------------------------------------- | -------------------------- |
| **발행됨** (`is_published = true`)    | 공개 블로그 목록에 노출    |
| **임시저장** (`is_published = false`) | 관리자만 확인 가능, 미노출 |

- 발행 후 수정 시 즉시 반영됨
- 삭제는 복구 불가 (신중히)

### 7-4. 마크다운 작성 가이드

```markdown
# 제목 1

## 제목 2

### 제목 3

**굵게** / _기울임_ / ~~취소선~~

- 목록 1
- 목록 2

1. 순서 목록 1
2. 순서 목록 2

> 인용문

[링크 텍스트](https://url.com)

![이미지 설명](https://image-url.com/image.jpg)

`인라인 코드`
```

## 8. 미디어 관리

**메뉴 경로**: `/admin/media`

### 8-1. 지원 플랫폼

| 플랫폼         | 아이콘                 | URL 형식                                                            |
| -------------- | ---------------------- | ------------------------------------------------------------------- |
| YouTube        | 빨간 재생 아이콘       | `https://youtube.com/watch?v=XXXXXX` 또는 `https://youtu.be/XXXXXX` |
| Instagram      | 핑크 그라데이션 아이콘 | `https://instagram.com/p/XXXXXX`                                    |

### 8-2. 미디어 항목 등록

| 필드       | 필수 | 설명                      |
| ---------- | ---- | ------------------------- |
| 플랫폼     | ✅   | youtube / instagram / x   |
| URL        | ✅   | 원본 콘텐츠 URL           |
| 제목       |      | 카드에 표시될 제목        |
| 썸네일 URL |      | 미리보기 이미지 URL       |
| 설명       |      | 짧은 설명 텍스트          |
| 날짜       |      | 게시 날짜 (YYYY-MM-DD)    |
| 메인 노출  |      | 홈페이지 미디어 섹션 노출 |

### 8-3. YouTube 썸네일 자동 URL

YouTube 영상 ID를 알면 아래 URL로 썸네일을 직접 사용할 수 있습니다:

```
https://img.youtube.com/vi/{영상ID}/maxresdefault.jpg
https://img.youtube.com/vi/{영상ID}/hqdefault.jpg
```

예시: `https://img.youtube.com/vi/dQw4w9WgXcQ/hqdefault.jpg`

### 8-4. 메인 노출 관리

- **메인 노출(is_featured)** 체크 시 홈페이지 "미디어" 섹션에 표시
- 최대 3개까지 홈페이지에 표시됨 (최신순)

## 9. 문의 관리

**메뉴 경로**: `/admin/inquiries`

### 9-1. 문의 유형

| 유형          | 코드            |
| ------------- | --------------- |
| 공간 대관     | `space_rental`  |
| 프로그램 문의 | `program`       |
| 협업 제안     | `collaboration` |
| 기타          | `other`         |

### 9-2. 문의 상태 관리

| 상태        | 의미          | 조치           |
| ----------- | ------------- | -------------- |
| `pending`   | 접수됨 (신규) | 검토 시작 전   |
| `reviewing` | 검토 중       | 담당자 처리 중 |
| `resolved`  | 처리 완료     | 응답/해결됨    |
| `closed`    | 종료          | 완전 종료      |

### 9-3. 문의 처리 절차

3. 상태를 `reviewing`으로 변경
4. 이메일/전화로 고객에게 답변
5. 처리 완료 후 상태를 `resolved`로 변경
6. 메모 필드에 처리 내용 기록 (선택)

## 12. 이미지 URL 관리

### 12-1. 이미지 URL 사용 방식

현재 플랫폼은 외부 이미지 URL을 직접 입력하는 방식을 사용합니다.

**권장 이미지 소스:**

| 소스         | URL 형식                                            | 특징           |
| ------------ | --------------------------------------------------- | -------------- |
| Unsplash     | `https://images.unsplash.com/photo-[ID]?w=800&q=80` | 무료 고품질    |
| 자체 CDN     | 별도 S3 또는 Supabase Storage 업로드 후 URL 사용    | 직접 관리 가능 |
| Google Drive | 공유 링크 변환 필요 (비권장)                        | 불안정         |

### 12-2. Unsplash URL 형식

```
https://images.unsplash.com/photo-{사진ID}?w=800&q=80&auto=format&fit=crop
```

파라미터 가이드:

- `w=800` — 가로 크기 (픽셀)
- `h=600` — 세로 크기 (픽셀)
- `q=80` — 품질 (1-100)
- `fit=crop` — 크롭 방식
- `auto=format` — 브라우저 최적 포맷 자동 선택

### 12-3. Supabase Storage 사용 (권장)

직접 이미지를 업로드하여 안정적인 URL을 사용하려면:

1. Supabase 대시보드 → **Storage** 메뉴
2. **New bucket** 클릭 → 이름: `images`, Public 설정
3. 이미지 파일 업로드
4. 업로드된 파일 클릭 → **Get URL** 복사
5. 어드민 폼의 이미지 URL 필드에 붙여넣기

**Storage URL 형식:**

```
https://ifadgzgiowsyhztylgrd.supabase.co/storage/v1/object/public/images/파일명.jpg
```

## 14. 문제 해결 가이드

### 14-1. 로그인이 안 되는 경우

| 증상                 | 원인                       | 해결 방법               |
| -------------------- | -------------------------- | ----------------------- |
| 이메일/비밀번호 오류 | 잘못된 비밀번호            | 비밀번호 재설정         |
| 페이지가 계속 로딩됨 | 네트워크 오류              | 새로고침, 인터넷 확인   |
| "권한 없음" 오류     | role이 admin 아님          | SQL로 role 확인 및 수정 |
| 환경변수 오류        | `.env.local` 없거나 잘못됨 | 환경변수 재확인         |

### 14-2. 저장이 안 되는 경우

| 증상         | 원인               | 해결 방법                 |
| ------------ | ------------------ | ------------------------- |
| 폼 저장 실패 | 필수 필드 미입력   | 빨간 테두리 필드 확인     |
| 슬러그 오류  | 중복 슬러그        | 다른 슬러그 값 입력       |
| 서버 오류    | Supabase 연결 문제 | Supabase 상태 페이지 확인 |

### 14-3. 이미지가 안 보이는 경우

1. 이미지 URL이 올바른지 브라우저에서 직접 접속하여 확인
2. Unsplash URL의 경우 사진 ID가 유효한지 확인
3. 외부 URL이 CORS 정책으로 차단되지 않는지 확인
4. 안정적인 이미지를 위해 Supabase Storage 사용 권장

### 14-4. 콘텐츠가 웹사이트에 반영 안 되는 경우

- 브라우저 캐시 문제: `Ctrl + Shift + R` (강력 새로고침)
- React Query 캐시: 데이터 staleTime 경과 후 자동 갱신 (공간 5분, 프로그램 2분 등)
- 즉시 반영 필요 시: 브라우저 개발자 도구 → Application → Clear storage
