## 2. 관리자 계정 및 권한

> **공급자 전용** — THE LIT 운영자는 계정 발급·관리를 공급자에게 요청해야 합니다.

### 2-1. 계정 발급 절차

1. [Supabase 대시보드](https://supabase.com/dashboard) 접속
2. 프로젝트 선택 → **Authentication → Users** 이동
3. **Invite user** 클릭 → 대상자 이메일 입력
4. 초대 이메일 수신 후 비밀번호 설정 완료
5. **SQL Editor**에서 role 부여:

```sql
-- 운영자 계정 (신규 기본값 — 별도 SQL 불필요)
-- 단, super_admin 부여 시:
UPDATE public.profiles
SET role = 'super_admin'
WHERE email = 'baikal-admin@email.com';

-- 운영자 계정 명시 설정
UPDATE public.profiles
SET role = 'operator'
WHERE email = 'thelit-operator@email.com';
```

### 2-2. 권한 체계

| 권한 레벨 | role 값       | 접근 범위                          |
| --------- | ------------- | ---------------------------------- |
| 공급자    | `super_admin` | 전체 어드민 + Supabase 대시보드    |
| 운영자    | `operator`    | 어드민 CMS (콘텐츠·운영 정보 관리) |
| 뷰어      | `viewer`      | 읽기 전용 (추후 확장용)            |

**operator 접근 가능 메뉴**: Dashboard, Spaces, Programs, Archive, Blog, Media, Inquiries, 운영 정보  
**super_admin 추가 접근**: Hero 슬라이드, About 페이지, 시스템 설정, 콘텐츠 소스, 외부 콘텐츠, 예약 관리, AI 사진 큐레이터

> **계정 발급 기본값**: 신규 초대 계정은 `operator`로 생성됩니다.  
> `super_admin` 부여는 공급자 담당자가 SQL로 직접 수행합니다.

### 2-3. 계정 비활성화

퇴직·이직 등 접근 권한 회수 필요 시:

```sql
-- role을 viewer로 다운그레이드 (로그인은 유지되나 CMS 접근 불가)
UPDATE profiles SET role = 'viewer' WHERE email = '대상자@email.com';
```

또는 Supabase 대시보드 **Authentication → Users**에서 직접 삭제합니다.

### 2-4. 비밀번호 초기화

Supabase 대시보드 → **Authentication → Users** → 해당 사용자 선택 → **Reset password** 클릭

## 3. 데이터베이스 관리 (Supabase)

> **공급자 전용** — DB 직접 조작은 공급자만 수행합니다.

### 3-1. 접속 정보

- URL: `https://supabase.com/dashboard`
- 프로젝트: **baikal-spacehub** (`ifadgzgiowsyhztylgrd`)

### 3-2. 테이블 구조

| 테이블            | 설명            | 주요 컬럼                                  |
| ----------------- | --------------- | ------------------------------------------ |
| `profiles`        | 관리자 사용자   | id, email, role                            |
| `spaces`          | 공간 정보       | slug, name, category, is_available         |
| `programs`        | 문화 프로그램   | slug, title, category, status, is_featured |
| `archive_items`   | 아카이브 기록   | title, category, year, is_featured         |
| `blog_categories` | 블로그 카테고리 | name, slug                                 |
| `blog_posts`      | 블로그 포스트   | slug, title, is_published, is_featured     |
| `media_items`     | 미디어 피드     | platform, url, thumbnail_url, is_featured  |
| `inquiries`       | 문의 접수       | inquiry_type, status, name, email          |
| `settings`        | 사이트 설정     | key, value                                 |

### 3-3. Row Level Security (RLS) 정책

| 테이블        | 읽기             | 쓰기/수정     | 삭제        |
| ------------- | ---------------- | ------------- | ----------- |
| spaces        | 공개             | 관리자 전용   | 관리자 전용 |
| programs      | 공개             | 관리자 전용   | 관리자 전용 |
| archive_items | 공개             | 관리자 전용   | 관리자 전용 |
| blog_posts    | 발행된 것만 공개 | 관리자 전용   | 관리자 전용 |
| media_items   | 공개             | 관리자 전용   | 관리자 전용 |
| inquiries     | 관리자 전용      | 누구나 INSERT | 관리자 전용 |
| settings      | 공개             | 관리자 전용   | 관리자 전용 |

### 3-4. 운영 SQL 쿼리

```sql
-- 모든 공간 조회
SELECT * FROM spaces ORDER BY created_at DESC;

-- 진행 중 프로그램 조회
SELECT * FROM programs WHERE status IN ('upcoming', 'ongoing');

-- 미처리 문의 조회
SELECT * FROM inquiries WHERE status = 'pending' ORDER BY created_at DESC;

-- 발행된 블로그 포스트 조회
SELECT * FROM blog_posts WHERE is_published = true ORDER BY created_at DESC;

-- 계정 role 확인
SELECT email, role FROM profiles WHERE email = 'admin@thelit.kr';
```

### 3-5. 블로그 카테고리 추가

카테고리는 SQL로만 관리합니다 (운영자 UI 미제공).

```sql
INSERT INTO blog_categories (name, slug)
VALUES ('전시 리뷰', 'exhibition-review');
```

## 4. 이미지 스토리지 관리

> **공급자 전용** — 버킷 생성 및 스토리지 설정은 공급자가 관리합니다.  
> 운영자에게는 업로드된 URL만 전달합니다.

### 4-1. Supabase Storage 설정

1. Supabase 대시보드 → **Storage** 메뉴
2. **New bucket** 클릭 → 이름: `images`, Public 설정
3. 이미지 파일 업로드
4. 업로드된 파일 클릭 → **Get URL** 복사 후 운영자에게 전달

**Storage URL 형식:**

```
https://ifadgzgiowsyhztylgrd.supabase.co/storage/v1/object/public/images/파일명.jpg
```

### 4-2. 외부 이미지 URL 가이드 (운영자 안내용)

운영자가 Unsplash 등 외부 URL을 사용할 경우 아래 형식을 안내합니다.

```
https://images.unsplash.com/photo-{사진ID}?w=800&q=80&auto=format&fit=crop
```

| 파라미터      | 설명                         |
| ------------- | ---------------------------- |
| `w=800`       | 가로 크기 (픽셀)             |
| `h=600`       | 세로 크기 (픽셀)             |
| `q=80`        | 품질 (1–100)                 |
| `fit=crop`    | 크롭 방식                    |
| `auto=format` | 브라우저 최적 포맷 자동 선택 |

### 4-3. YouTube 썸네일 URL

```
https://img.youtube.com/vi/{영상ID}/maxresdefault.jpg
https://img.youtube.com/vi/{영상ID}/hqdefault.jpg
```

## 6. 문의 관리

> **operator 이상 접근 가능** — operator(THE LIT 운영자)가 기본 담당자이며,  
> super_admin도 동일하게 접근 가능합니다.

**메뉴 경로**: `/admin/inquiries`

### 6-1. 문의 유형

| 유형          | 코드            |
| ------------- | --------------- |
| 공간 대관     | `space_rental`  |
| 프로그램 문의 | `program`       |
| 협업 제안     | `collaboration` |
| 기타          | `other`         |

### 6-2. 문의 상태 관리

| 상태        | 의미          | 조치           |
| ----------- | ------------- | -------------- |
| `pending`   | 접수됨 (신규) | 검토 시작 전   |
| `reviewing` | 검토 중       | 담당자 처리 중 |
| `resolved`  | 처리 완료     | 응답/해결됨    |
| `closed`    | 종료          | 완전 종료      |

### 6-3. 처리 절차

1. 새 문의(`pending`) 확인
2. 문의 클릭 → 상세 내용 확인 (이름, 이메일, 전화, 메시지)
3. 상태를 `reviewing`으로 변경
4. 이메일/전화로 응답
5. 처리 완료 후 상태를 `resolved`로 변경
6. 메모 필드에 처리 내용 기록 (선택)

### 6-4. 확인 가능한 문의 정보

| 필드      | 설명                        |
| --------- | --------------------------- |
| 이름      | 문의자 이름                 |
| 이메일    | 연락 이메일 (선택 제출)     |
| 전화번호  | 연락처 (선택 제출)          |
| 예상 인원 | 공간 대관 시 예상 참가 인원 |
| 희망 날짜 | 요청 날짜                   |
| 메시지    | 상세 문의 내용              |
| 접수 일시 | 시스템 자동 기록            |

## 7. 보안 관리

> **공급자 전용** — API 키·환경변수·접근 권한은 공급자만 관리합니다.

### 7-1. API 키 보안

> ⚠️ `VITE_SUPABASE_ANON_KEY`는 공개 키이므로 브라우저에 노출됩니다.  
> `service_role` 키는 절대 프론트엔드 코드에 포함하지 마세요.

**키 교체 방법 (유출 시):**

1. Supabase 대시보드 → **Settings → API**
2. **Regenerate** 클릭 (기존 키 즉시 무효화)
3. `.env.local` 업데이트:
   ```env
   VITE_SUPABASE_URL=https://ifadgzgiowsyhztylgrd.supabase.co
   VITE_SUPABASE_ANON_KEY=새로운_키_값
   ```
4. Vercel 대시보드 → **Settings → Environment Variables** 업데이트
5. Vercel **Redeploy** 실행

### 7-2. 로그인 보안 정책

- 비밀번호: 12자 이상, 대소문자 + 숫자 + 특수문자 조합
- 비밀번호 주기적 변경 권장 (3개월)
- 공용 컴퓨터 접속 금지
- 사용 후 반드시 로그아웃

## 8. 백업 및 복구

> **공급자 전용** — 백업 정책 및 복구는 공급자가 관리합니다.

### 8-1. 자동 백업 (Supabase 기본 제공)

- Pro 플랜: 일별 자동 백업 (7일 보관)
- Free 플랜: 수동 백업 필요

### 8-2. 수동 백업

1. Supabase 대시보드 → **Database → Backups**
2. **Create backup** 클릭
3. 또는 Supabase CLI 사용:

```bash
supabase db dump -f backup_$(date +%Y%m%d).sql
```

### 8-3. 콘텐츠 내보내기

```sql
COPY spaces TO '/tmp/spaces_backup.csv' CSV HEADER;
COPY programs TO '/tmp/programs_backup.csv' CSV HEADER;
```

### 8-4. 복구 절차

1. 백업 파일 준비
2. Supabase SQL Editor에서 복구 SQL 실행
3. 또는 Supabase 대시보드 → **Backups → Restore**

## 9. 문제 해결 가이드

> **공급자 전용** — 시스템 오류 대응은 공급자가 담당합니다.  
> 운영자가 이슈를 보고하면 공급자가 아래 항목을 기준으로 진단합니다.

### 9-1. 로그인 오류

| 증상                 | 원인                       | 해결 방법               |
| -------------------- | -------------------------- | ----------------------- |
| 이메일/비밀번호 오류 | 잘못된 비밀번호            | 비밀번호 재설정         |
| 페이지가 계속 로딩됨 | 네트워크 오류              | 새로고침, 인터넷 확인   |
| "권한 없음" 오류     | role이 admin 아님          | SQL로 role 확인 및 수정 |
| 환경변수 오류        | `.env.local` 없거나 잘못됨 | 환경변수 재확인         |

### 9-2. 저장 오류

| 증상         | 원인               | 해결 방법                 |
| ------------ | ------------------ | ------------------------- |
| 폼 저장 실패 | 필수 필드 미입력   | 빨간 테두리 필드 확인     |
| 슬러그 오류  | 중복 슬러그        | 다른 슬러그 값 입력       |
| 서버 오류    | Supabase 연결 문제 | Supabase 상태 페이지 확인 |

### 9-3. 이미지 표시 오류

1. 이미지 URL을 브라우저에서 직접 접속하여 유효 여부 확인
2. 외부 URL의 CORS 정책 차단 여부 확인
3. 안정적인 이미지 제공을 위해 Supabase Storage 사용 권장

### 9-4. 콘텐츠 미반영

- 브라우저 강력 새로고침: `Ctrl + Shift + R`
- React Query 캐시: staleTime 경과 후 자동 갱신 (공간 5분, 프로그램 2분 등)
- 즉시 반영 필요 시: 개발자 도구 → Application → Clear storage

## 17. Photo Projects — 이미지 자산 관리

### 17-1. 개요

Photo Projects는 촬영 프로젝트별로 이미지 자산을 체계적으로 분류·관리하는 시스템입니다.

**접속 경로**: 관리자 사이드바 → 이미지 자산 관리 (`/admin/photo-projects`)

### 17-2. 구조 개념

```
프로젝트 (예: "THE LIT 2026")
└── Category × Stage 격자
    ├── Category: Main / Wedding / Space / F&B / Archive / Online Wedding / Online Space / Contact / About
    └── Stage:    Source → Selected → Edited → Web → PDF
```

각 셀(Category + Stage 교차점)에 사진을 업로드하면 Storage에 구조화된 경로로 저장됩니다.

**Storage 경로 규칙**:
```
photos/{slug}/{category}/{stage}/{uuid}.{ext}
예: photos/the-lit-2026/main/web/a1b2c3.jpg
```

### 17-3. 프로젝트 관리

#### 프로젝트 생성

1. `새 프로젝트` 버튼 클릭
2. **프로젝트명** 입력 (slug 자동 생성 — 영문·한글 지원)
3. **카테고리** 선택 (1개 이상 — 사용할 분류 체계)
4. **관리 단계** 선택 (기본: 5단계 전체)
5. 저장

> **주의**: 프로젝트명이 동일하면 slug에 자동 suffix(`-2`, `-3` …)가 붙습니다.

#### 프로젝트 수정

- 프로젝트명·설명·카테고리·단계·상태 수정 가능
- **slug는 변경되지 않습니다** — Storage 경로 안정성 보장

#### 프로젝트 아카이브

- `아카이브` 버튼 클릭 → 확인 → `status: archived`로 변경
- **실제 파일 삭제 없음** — 기존 사진은 Storage에 유지됩니다

### 17-4. Asset Explorer (이미지 탐색기)

프로젝트 목록에서 `탐색` 버튼을 클릭하면 해당 프로젝트의 Asset Explorer로 이동합니다.

#### 격자 구조

| | Source | Selected | Edited | Web | PDF |
|---|---|---|---|---|---|
| Main | 3 | 0 | 0 | 0 | 0 |
| Wedding | 12 | 5 | 2 | 1 | 0 |
| … | … | … | … | … | … |

숫자 배지 = 해당 셀의 사진 수

#### 이미지 업로드

1. 업로드하려는 셀의 `↑` 아이콘 클릭
2. 파일 선택 (복수 선택 가능)
   - 허용 형식: **JPG, PNG, WebP**
   - 최대 크기: **10MB / 파일**
3. 업로드 진행 표시: `1/5`, `2/5` … 순서대로 처리
4. 완료 후 배지 자동 갱신

#### 사진 목록 보기 (Slideout)

- 배지 클릭 → 우측에서 슬라이드 패널 열림
- 2열 썸네일 그리드로 목록 표시
- 사진 클릭 → Photo Detail 편집 화면

#### 사진 삭제

- 썸네일 위 `✕` 아이콘 클릭
- 삭제 순서:
  1. DB `upload_status → delete_pending`
  2. Storage 파일 삭제
  3. DB 레코드 삭제

> **주의**: 삭제는 즉시 실행되며 취소할 수 없습니다.

#### Photo Detail (메타데이터 편집)

슬라이드 패널에서 사진 클릭 시 진입합니다.

| 필드 | 설명 |
|------|------|
| 파일명 | 원본 파일 이름 (수정 불가) |
| 파일 크기 | 자동 표시 |
| 업로드일 | 자동 표시 |
| Category / Stage | 업로드 시 설정된 값 (수정 불가) |
| 제목 | 사진 제목 (선택) |
| 설명 | 사진 설명 텍스트 (선택) |
| 태그 | Enter 또는 쉼표로 추가, Backspace로 제거 |
| 메모 | 내부 메모 (관리자 전용, 공개 안 됨) |

- `Save` 버튼 활성화 조건: 입력값이 변경된 경우(Dirty check)
- `Cancel`: 마지막 저장 상태로 되돌림

## 18. Phase 2 예정 기능

> 아래 기능은 MVP 범위에서 제외되었습니다.  
> **Phase 2 이후** 순차적으로 제공될 예정입니다.  
> 현재 운영에서는 사용하지 않습니다.

### 17-1. 예약 관리 (CRM)

공간 대관 예약을 시스템 내에서 직접 관리하는 기능입니다.

- 예약 접수·확인·승인·취소 처리 (6단계 상태 관리)
- 고객 연락처 및 예약 이력 관리
- 캘린더 기반 예약 현황 뷰

> **현재 대안**: 문의 기능을 통해 대관 신청을 접수하고 이메일·전화로 직접 처리합니다.

### 17-2. 고객 CRM

문의 및 예약 이력을 기반으로 고객 정보를 관리하는 기능입니다.

- 고객 프로필 및 방문 이력 조회
- 문의·예약 연결
- 단골 고객 관리

### 17-3. 사진 AI 큐레이터

공간·프로그램 사진을 업로드하면 AI가 분석·태그·큐레이션하는 기능입니다.

- 이미지 업로드 및 AI 자동 분석
- 사진 태그 자동 생성
- 큐레이션 추천

### 17-4. 콘텐츠 소스 / 외부 콘텐츠 자동 수집

RSS·YouTube·Instagram·X 등 외부 채널의 콘텐츠를 자동으로 수집하는 기능입니다.

- 수집 소스 등록·관리
- 수집된 콘텐츠 공개/비공개 큐레이션
- 자동 갱신 주기 설정

### 17-5. 결제

온라인 티켓 판매 및 대관료 결제를 처리하는 기능입니다.

- PG사 연동 (카드·계좌이체·간편결제)
- 결제 내역 조회 및 환불 처리
- 정산 리포트
